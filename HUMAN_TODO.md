## Product decisions waiting on the owner
- **Linux memory budget (§5.1, D-138, D-140).** The spec's base app budget is 350 MB PSS (the app and its own WebKit processes, no panes). On Linux it can't be met by work on our side: WebKitGTK's web process alone measures 353 MB at 0590144, before any of the later features, and 368 MB now. What's ours: the core at 148–149 MB with release build settings (D-140) and the app's JavaScript at ~11 MB of heap; the whole app comes to ~548 MB on the perf build (52f07fe1, 4 vCPU, Xvfb, software GL). Options: (1) a Linux-specific budget set from the measured WebKitGTK floor; (2) WebKit's memory-pressure settings, which can return freed memory but are construct-only on `WebKitWebContext` (`memory-pressure-settings`). Tauri 2.12 creates that context through wry 0.57's builder with no hook to pass them, so wry would have to take them, upstream or as a `[patch]` (see BUILD_LOG M15 log, §5.1 background panes).
