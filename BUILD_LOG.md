- Desktop E2E: `dbus-run-session -- xvfb-run -a -s "-screen 0 1920x1080x24" pnpm --filter desktop e2e` runs the real Tauri binary via tauri-driver (starts API + web if needed, openbox for WM behaviour, scripted Chromium for sign-in and checkout). 60/60 spec files pass (about 10 minutes). Pass one glob to `--spec` (`m7-{8,10}-*`): the runner keeps only the first `--spec`. Restore specs crash the app with `pkill -9` and relaunch; they sign the same account in again because the test keychain lives in memory. The run starts `scripts/mock-update-feed.ts` on :8790 (scenario `none`). `--suite startup` needs `gnome-keyring` (D-101). `TANDEM_E2E_SKIP_BUILD=1` reuses the last build; `UPDATE_GOLDENS=1` rewrites the TUI goldens (review them). zsh, fish, vim, htop and less must be installed (`apt-get install zsh fish htop`).
- API tests need `pnpm infra:up` (they create `tandem_test`). Web E2E: `PLAYWRIGHT_CHROMIUM=/opt/pw-browsers/chromium pnpm --filter web test:e2e` after `db:migrate`, `db:seed`, `keys:dev`.

The Free plan's `chatEngines` limit (Claude Code and Codex in Thread mode, PRODUCT_SPEC §3.1) is defined but not enforced yet: Free threads also run the ACP engines; enforce it with the entitlement checks (the site makes no Free-plan engine claim). - D-202: Files backend details F-CD-19 leaves open. (1) A conflict is decided by the content hash (SHA-256) from when the editor read the file; the mtime is only reported, because two writes within one clock tick keep it. A file deleted since it was opened is a conflict too, and Overwrite reads the current hash and writes with it. (2) Writes keep the file's line endings (CRLF when most of its breaks are), BOM and mode. (3) Text that isn't UTF-8 opens as binary (hex placeholder) rather than being re-encoded on save. (4) Text over 5 MB opens read-only and is shown up to 20 MB, cut at a line; images up to 10 MB preview. (5) The watcher batches for 500 ms from the first event (a trailing debounce would never fire during a long build). On Linux it watches each folder `.gitignore` keeps rather than everything recursively, so an ignored `node_modules` costs no inotify watches. (6) Nothing named `.git` is created, renamed or deleted from the tree, and the context's own folder can't be deleted.
- D-203: Tab strips hold only tabs (ARIA: a `tablist` owns only `tab`s), which the Files tab's axe check found the M5 sidebar strip breaking. - D-206: The browser's pages are wry webviews the browser service creates itself, not Tauri webviews: a Tauri webview with no permissions still gets the IPC bridge (`__TAURI_INTERNALS__`, the `ipc:` scheme), a wry webview gets none, and it runs in its own WebKit context, where the app's schemes aren't registered. - D-209: `BrowserState` carries `seq`, a number that grows with every change in the core, and views keep only the newest state per page. A command's reply and the events that follow it travel separately, and a fast page (a local dev server) can commit, load and name itself before `browser_open`'s reply lands; without it the reply's "loading" state overwrote the loaded page for good. - D-210: The element picker runs in the page's own JavaScript and reports through navigations, so pages still get no IPC (D-206). Each time it's turned on, the core runs `picker.js` with a new random nonce. Each change sends the whole selection as a hidden frame's navigation to `tandem-picker://<nonce>/<JSON>`, which the navigation handler takes and never loads. wry hands over only the top frame's navigations on WebView2, so there (`BrowserHost::sees_frame_navigations`) the picker reports through `window.open`, which the new-window handler takes the same way; so does a page whose Content-Security-Policy refuses the frame, which the picker's first report (the empty selection) finds out before the first pick. A report without the session's nonce is ignored, so another page, a frame or an older session can't fill the selection. The page can still shape what the picker reports about it, as it can its own HTML, which the brief quotes anyway: the brief is only ever pasted, never submitted, and is held to 50 elements and 4 KB of HTML each. Component names come from what React and Vue keep on DOM nodes (React's fiber, `__reactFiber$…`, or `__reactInternalInstance$…` before React 17; Vue 3's `__vueParentComponent`, Vue 2's `__vue__`), not from a devtools hook as PRODUCT_SPEC suggests: a hook has to be in place before the page's own scripts run, so it would mean injecting a script into every page all the time, while the nodes give the same names to a picker turned on at any point. ### M16 · F-SH-12 decisions
- D-800: Saving is throttled, not debounced. PRODUCT_SPEC F-SH-12 says "debounced at 300 ms", but its acceptance 1 (killing the app within 1 s of typing keeps all but the last 300 ms) can't hold under a debounce while someone types without pausing: a debounce only fires after a pause. The first unsaved edit starts a 300 ms clock that later edits don't push back, so a save goes out at least every 300 ms of typing; writes go one at a time, in order. Opening another note, going back to the list, closing the panel and the window's `pagehide`/`beforeunload` write at once.
- D-801: `scratchpad_write` with an id only overwrites a note that still exists (`NotFound` otherwise), so a save that lands after a delete never brings the note back; without an id it creates one. Deleting a note also drops its waiting save. A note over 1 MB is refused (`Invalid`) and the saved copy stays. Ids must be `note_` ULIDs, so no command can name a file outside the folder.
- D-802: The Markdown each format writes: bold `**`, italic `*` (so bold italic is `***` and either toggles off without the other), underline `<u>…</u>` (Markdown has none; CommonMark renderers show the HTML tag), bullets `- `, checklist items `- [ ] ` / `- [x] `. Enter continues a bullet, numbered or checklist item (a new checklist item starts unticked) and ends the list on an empty one. The title drops heading, quote, list and checkbox marks and emphasis and keeps 80 characters; a note without one is "Untitled note".
- D-803: No new dependency. The editor reuses the CodeMirror packages and the lazily loaded Markdown language the Files editor already has, and the formatting and list commands are written in `@tandem/ui`.
- D-804: Release builds swallow the webview's own shortcuts (reload, print, find, save, view source, devtools; UI_SPEC §5) only after a focused editor has had the key. CodeMirror ignores a key whose default is already prevented, and the dispatcher prevented them in the capture phase, so in release builds the Files editor's `Mod+S` and the note editor's `Mod+U` did nothing. The E2E suite runs debug builds, where nothing is swallowed, so it couldn't see this. Outside editors the capture phase still swallows them, and inside one a bubble-phase listener swallows whatever the editor didn't handle.
