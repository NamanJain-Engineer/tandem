The download on this site doesn't contact Vibezeo's servers at all: no sign-in, no analytics, no crash reports and no update checks.

- **On your computer.** Workspaces, layouts, settings, threads, teammates, tasks, notes, Dictate's history and dictionary, file checkpoints, the commands you run in Vibezeo terminals (text that looks like a secret is stored redacted) and each agent session's Activity (turns without their words, tool names, approvals and `vibezeo run`s, for 14 days) are stored in the app's data folder, `~/.tandem/`.
- **Your data.** Settings › Privacy exports it to a zip (every table as JSON, teammates' memory and skills, your notes), without engine sign-ins or secrets, and can delete Vibezeo's data from this computer. Engine sign-ins stay unless you tick **Also remove engine sign-ins**.
- **Secrets** are stored only in your operating system's keychain. Logs are scrubbed of tokens and keys, and diagnostics contain no prompts, file contents or tokens.
- **Engines** talk to their vendors directly, under those vendors' terms, from their own provider homes. Vibezeo doesn't send your prompts, code or terminal output to us.
- **Dictate** recognizes speech on your computer. Audio is never saved or sent; the only network request is the model download you start, from Hugging Face.
- **Plugins** talk to each service directly from your computer, with the credential from your keychain. Nothing goes through Vibezeo's servers.
- **SSH hosts** you add are reached with your own `ssh`. Vibezeo keeps each host's name, address, port, key file path and key fingerprint, never a password or a key.
- **Usage statistics and crash reports** are off by default and stay off unless you turn them on in Settings › Privacy.

The full list of what the app can send once Vibezeo accounts open, where to and when, and who processes it, is on the [privacy page](/privacy/). The app shows the same list in Settings › Privacy.

## Agent-proof secrets

Agents read `.env` files, so a key written there ends up in their context, their transcripts and every worktree copy. Keep the value in your keychain and put a reference in the file instead.

1. **Settings › Secrets › Add secret.** Give it a name (`stripe-test`) and paste the value. It's saved in your system keychain; Vibezeo keeps only the name and never shows the value again.
2. **In the folder's `.env`,** use the reference as the value: `API_KEY=vibezeo-secret://stripe-test`. Agents, diffs and worktree copies see only that text.
3. **Run the command** with the play button in a terminal pane's header (or "Run with secrets…" in its menu). The dialog lists what the `.env` uses and names any secret that's missing. Run opens a new pane beside it in the same folder: the command gets every `.env` variable with the references replaced, and when it exits the variables are unset before the shell takes over.

In that pane, a secret value the command prints shows as `[REDACTED]`, on screen, in its scrollback and in what Vibezeo saves or reads from the pane.

What it doesn't cover:

- A command that's given a secret can use it, write it to a file or print it encoded; only the exact value is masked, and only in that pane.
- These forms of a value show unmasked:
  - values under 4 bytes (Settings › Secrets warns when you enter one);
  - a value printed in parts more than 50 ms apart;
  - a value printed with colours or other escape codes inside it, or JSON-escaped, URL-encoded or otherwise encoded;
  - a value a full-screen program draws in pieces as it redraws the screen.
- Programs the command starts in the background keep the values after it exits; only the shell after it starts without them.
- Chat threads, routines and the Night Shift can't use secrets: they have no pane to ask in.
- The Flatpak build can't run with secrets yet.

### Agents: `vibezeo run`

An agent in an agent pane runs a command that needs secrets as `vibezeo run -- pnpm deploy`. The agent never sees the values: Vibezeo runs the command itself and hands back what it printed.

1. **The pane asks first,** on the pane and its Dashboard card: the whole command, the folder it runs in and every variable it gets, by name and secret name, never a value. Choose **Allow once**, **Allow for this agent** (that exact command in that folder, until you close the pane) or **Deny**. Unanswered after 30 minutes, it's denied. The notification, and the phone companion, say only that an agent wants to run a command with secrets: you answer on your computer, and the phone offers no Allow for it. A pane asks one question at a time; a second `vibezeo run` while one waits is refused, and Allow ignores clicks for half a second after the question changes. On the pane the buttons come after the command, which scrolls within the pane, and Allow stays off until you've had the command's end in view (scrolling the question to its end counts, and a new question starts at the top). Conductor hears only that an agent wants to run a command with secrets. If `vibezeo run` is stopped while it waits (the agent killed it, or its tool timed out), the question is withdrawn; if it's stopped while the command runs, the command and what it started are ended, and Activity says so. Quitting or restarting Vibezeo ends every running `vibezeo run` the same way. A pane can ask at most 10 times a minute, and a rule or "Allow for this agent" runs at most 30 commands a minute without asking. Each Allow also waits until its own place on screen has held still for half a second, so a card moving above it, a scroll or the panel appearing can't slide another question's Allow under your click; cards with a question come first, above everything else on the Dashboard and whatever it's filtered to, in the order they asked, so what other agents report doesn't move them. A card still moves when a question asked before it is answered or withdrawn, and its Allow then waits again. Allow also waits while anything covers it or Allow for this agent, even a corner of one; a toast over Deny doesn't hold it, and neither does a menu open elsewhere. The same wait guards the notification list's Allow once, a chat's Allow and Allow for this thread (and their keys, which answer only the card you're on), held actions' Approve & run and the picks that feed Approve & run for several, the review queue's Approve (which also waits again when the diff changes), a phone's queued Allow in Settings › Remote, Trust and connect for a new SSH host key, Trust and run for a repository's worktree setup, Keep for an agent's or Conductor's memory suggestions, Plan with Lead's Run (which appears where Execute all… was), Edit & run's Run, the pull-request checks' Allow, and Allow on the phone itself, on the web and in the app (each answer from the phone is sent once). A card scrolled out of view takes no key, even if it still has focus. A panic on Vibezeo's main thread ends running commands too; a native crash, the system ending Vibezeo for memory, or `kill -9` doesn't, and those commands keep running.
2. **Vibezeo runs it** in the agent's folder (it must be the pane's folder or a folder inside it), with your login environment and the `.env`'s secret references, replaced by their values, for up to 10 minutes. Plain values in `.env` aren't passed, and a reference under a variable that changes what programs load or run (`LD_PRELOAD`, `NODE_OPTIONS`, `PATH`, `GIT_*` and others) is refused. It runs outside the agent's sandbox, which is why it asks. When it ends, anything it left running in its process group is ended too; a program that starts its own session (`setsid`) can outlive it.
3. **The agent gets the output**, the last 64 KB with every secret value shown as `[REDACTED]`, and the command's exit code.

One argument is a command line for the shell (`vibezeo run 'pnpm build && pnpm deploy'`); several are a program and its arguments. The question shows exactly what will run, whole and left to right, with every variable it gets. Characters that show as nothing or reorder the text around them (Unicode's default-ignorable code points, format controls, line and paragraph separators, and every space but the plain one) are refused. Any other character outside plain ASCII, such as a Cyrillic `і` in a host name or right-to-left text, is shown marked, by its code point (`\u{456}`), so check it before you allow. If the agent changes `.env` afterwards, "Allow for this agent" and rules ask again.

- **Commands agents can run without asking** (Settings › Secrets): per folder, a command such as `pnpm deploy`. It then runs with any arguments (`pnpm deploy --prod`), never chained, piped or redirected (`pnpm deploy; rm -rf x` still asks). Worktrees use their folder's rules. The first run under a rule, and the first after `.env` changes, still asks. A rule on a command that runs the repository's own scripts (`pnpm deploy`, `npm run`, `make`) lets the agent change what runs by editing those scripts. Since any arguments are allowed, some name another program, file or host (`git push --receive-pack=…`, `make -f`, `npm --registry`), and the repository's config changes what runs too (`.npmrc`, `yarnPath` in `.yarnrc.yml`, `bunfig.toml`, `rust-toolchain.toml`). When a rule asks again because `.env` changed, allowing it, even once, lets the rule run it with that `.env` from then on.
- **Tell agents in this folder** (in the Run with secrets dialog) adds one paragraph to the folder's `AGENTS.md`, shown as a change first: put `vibezeo run --` before commands that need secrets. It names no secrets.
- `vibezeo run` says why and exits 1 outside an agent pane, in SSH and WSL panes, in the Flatpak build, for a missing secret and when you deny. On Windows it runs commands with `cmd /D /V:OFF /S /C`, without looking in the current folder for a bare command name, and hasn't been tested there yet. Empty and relative `PATH` entries are left out of every run's environment (with none left, it gets the system's default `PATH`).
- The pane's question isn't stored, and its notification says only that an agent wants to run a command with secrets. The session's Activity keeps, for 14 days, that a question was asked and the answer (where it came from), and each run's command (with token-shaped text redacted), the variables it got (names and secret names), who decided, its exit code and duration (a run that didn't start keeps no command, since its values were never read). Runs and answers stay the full 14 days however many other events the agent reports. Never its output or a value.
- What "agent-proof" covers: an agent that uses `vibezeo run` never holds the values. It doesn't stop another program running as you from reading your keychain or Vibezeo's memory, and a pane's requests are tied to it by a secret in its environment.

Settings › Privacy › Delete local data… removes every secret from the keychain too.
